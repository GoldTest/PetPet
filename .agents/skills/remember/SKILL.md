# Skill: remember — 项目记忆管理

## 概述

维护 `.remember/` 文件夹作为项目的长期记忆库。所有需要跨会话保留的信息（重要决策、提示词、
经验教训、用户偏好、流程约定）都以 Markdown 文档形式存放，供后续会话检索参考。

## 记忆库位置

```
.remember/                    ← 记忆库根目录（文件夹，不是文件！）
├── 01-herb-stage2-4-5-提示词.md    ← 按主题编号的文档
└── 02-树类-stage3-5-真实纹理提示词.md
```

## 触发场景

| 触发 | 行为 |
|------|------|
| 用户说"记住/记下来/记忆" + 内容 | 写入记忆：将内容整理成文档存入 `.remember/` |
| 用户说"回忆/参考/查一下之前" | 检索记忆：先读取 `.remember/` 全部文档，提取相关内容用于当前任务 |
| 用户说"修改记忆/更新记忆/改正" | 修改记忆：编辑对应文档，保持结构完整 |
| 用户说"删除记忆/移除" | 删除对应文档（需用户明确指定主题） |

## 写入记忆规范

1. **主题分文件**：一个主题一份文档，不把所有内容塞进一个文件。
   文件名格式：`NN-主题-描述.md`（NN 为两位序号，主题用业务名，描述用关键词）。
   例：`01-herb-stage2-4-5-提示词.md`、`03-打包规则.md`
2. **内容要可复用**：记录完整细节（提示词全文、完整参数、完整决策理由），
   不要只写摘要——记忆的价值在于后续可以直接照做。
3. **记录元信息**：文档开头写明批次/日期、文件对应关系（如生成图文件名、路径）。
4. **结构清晰**：用 `#`/`##` 标题分层，列表列出要点。
5. **中文书写**：与项目文档语言一致，中文为主。
6. **写完后汇报**：告知用户写入的文件路径与包含的内容概要。

## 检索记忆规范

1. 当任务涉及"过往做过的事/以前的决定/历史参数"时，**先列出 `.remember/` 下的所有文档**。
2. 读取相关文档，把其中的要点应用到当前任务（如复用提示词模板、沿用既有规格）。
3. 若用户说"参考当时的做法"而记忆中没有，明确告知"记忆库中无此记录"，不要编造。
4. 检索结果在回复中体现：简要说明参考了哪份记忆、用了其中什么。

## 修改记忆规范

1. 用户要求修改记忆时，先定位对应文档（按主题匹配文件名）。
2. 用编辑工具直接修改文档内容，保持原有结构和格式。
3. 修改后汇报：改了哪个文件、改了什么。
4. 若修改涉及编号顺序（新增文档），新文档序号延续最大值 +1。

## 注意事项

1. `.remember/` 是文件夹——文件不能与目录同名，转换时先重命名再建目录。
2. 记忆文档不要写临时内容（如一次性测试结果）；临时内容放对话即可。
3. 大段提示词类记忆，用代码块包裹原文，确保可原样复用。
4. 记忆库结构变化（增删文档）后，保持 `NN-` 序号连续。
